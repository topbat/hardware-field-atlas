# 研发工作台调研

本文面向做逆向、选型、移植和原型验证的人。优先解决四个问题：这是哪个版本，手上有哪些原始材料，哪部分可以复现，以及实测结果在什么条件下成立。

| 参考实践 | 对工作台的要求 |
| --- | --- |
| [iFixit 可维修性](https://www.ifixit.com/repairability)区分拆装设计、工具、文档、零件和软件配对 | 用拆装路径、替换件、工具和固件依赖描述可维修性。没有实测时不发布评分 |
| [Interactive HTML BOM](https://github.com/openscopeproject/InteractiveHtmlBom)把位号、BOM 行和 PCB 视图联动 | 以稳定部件 ID 链接 2D、3D、BOM 和证据。将来增加正反面 PCB、位号、网络高亮和替代料筛选 |
| [KiCad PCB 编辑器文档](https://docs.kicad.org/9.0/en/pcbnew/pcbnew.html)区分电气、机械和制造输出 | 资产按原理图、PCB、网表、Gerber、坐标、CAD、固件和说明归类。每件标版本、许可、哈希和原文入口 |
| [OSHWA 文档要求](https://certification.oshwa.org/process/documentation.html)强调可编辑设计、BOM、说明和许可 | 对开源项目列出能下载的源文件与许可。商品拆解重建仍标为研究示意 |
| [Zephyr 板级开发指南](https://docs.zephyrproject.org/latest/hardware/porting/board_porting.html)描述板级支持和硬件描述 | 用 SoC、板版、引脚、电压、接口、固件和工具链版本定位复现条件 |
| [Edge Impulse 部署资料](https://docs.edgeimpulse.com/docs/run-inference/deploy-your-model)把推理打包到目标硬件 | 建立实测记录，至少含模型/精度、运行时、板版、电源、环境、延迟、内存占用和测量方法 |

## 按工作顺序交付

1. **当前可用。** 搜索整机和厂商料号，按场景与推理位置筛选，跨设备对比；在有证据的机型里打开结构、规格、BOM 和原始来源。网页体验可下载 BOM，并可将研究笔记留在浏览器。
2. **下一批：先做到可核验。** 建立 SKU、区域、硬件修订和固件版本的区分；为规格、部件、媒体增加来源位置与验证时间。对 PCB 位号、引脚、电压、替代料和原厂源文件设置单独的证据字段。记录作者与许可，控制引用和下载边界。
3. **随后：复现和对比实测。** 用清单串起环境、依赖、烧录、校准、运行样例和验收条件。对性能与功耗只比较可解释的测试条件，同一 NPU 理论 TOPS 与实测时延用不同字段。发布者可提交测量数据、脚本与复现日志。
4. **规模扩大后：按关系查找。** 让料号、传感器、芯片与设备形成可跳转的索引。对同一器件的替代方案保留制造商、封装、接口、功耗、供货区域和证据状态，避免把“外形相近”当作可直接替换。

新增设备的最低门槛是明确型号、一个可验证的智能能力、相关硬件字段和可打开的原始资料。有公开外观时展示并注明来源，拆解、内部结构或实测不清楚时保留待核验状态。
