## 首发交互

- **研究台。** 入口紧跟当前页面，携带产品和用户所选部件。结果先呈现对问题的短答，下一行列证据，折叠区域展开「定位范围」「汇集证据」「核对与归纳」的真实状态和耗时。三套快捷工作流对应拆解、型号对比、离线和隐私。手动设置范围在发送前可见。
- **研究笔记。** 一键把问题、回答所用证据和当前产品记入本会话。显式记忆适合「只看国内品牌」「关注端侧语音」这样的稳定偏好，项目内的产品选择单独保存。默认只使用会话范围内的少量上下文。提供清空和删除操作。
- **从图找零件。** 静态照片上传需要主动触发。助手先展示可见文字和特征，再检索产品及 BOM 候选。候选卡说明证据来自目录、图像观察或两者。图片无法辨认时，提示拍更近的芯片丝印或板号。生成的结构图标明为示意，既有实物和模型热点由编辑提供。
- **先查料号。** 型号、丝印和制造商料号采用精确命中优先。中文短词保留别名和子串匹配。SQLite FTS5 的 trigram 全文查询对不足三个 Unicode 字符的关键词有局限，应保留短词路径。[SQLite FTS5 文档](https://www.sqlite.org/fts5.html)

## 实现与验收

FastAPI 和 SQLite 即可支撑第一版。用小型、可测试的 Python 工作流分别执行范围识别、目录检索、证据归纳，逐步收集状态、证据数和耗时。模型服务通过部署端配置的 OpenAI 兼容 Chat Completions 接口接入，文本和视觉模型分别配置。密钥只在服务器使用。未配置文本模型时可提供可预测的目录证据摘要并标明模式。未配置视觉模型时，显示真实状态，保留手动输入丝印的检索入口。

模型只收到本次检索返回的有界证据池。以结构化的证据 ID 作为引用接口，服务器核对是否在本次证据范围内，由服务器展开为可打开的 URL。匹配不到可信证据时返回资料缺口。证据、图片文字和记忆按数据处理，模型无法根据其中的指令调用任意网络、文件、写库或外部消息操作。图像限制尺寸和体积并在内存重编码，传给配置的视觉服务前在界面提示处理方式。

验收可用五个真实场景：指定部件时缩小检索；同一产品的两份拆解记录分别保留；无证据问题显示缺口；删除记忆后新请求不再使用；图像候选保留可观察文本、证据链接和不确定性。单实例部署可通过 SQLite WAL、短事务和持久磁盘保存研究记录，多实例共享部署需迁移到共享事务数据库。

## 运行配置

| 变量 | 默认值 | 行为 |
|---|---:|---|
| `ATLAS_RESEARCH_RUNS_PER_IP_PER_MINUTE` | 8 | 单个远端地址在一个滑动分钟内可提交的研究请求数，上限 600。 |
| `ATLAS_RESEARCH_RUNS_GLOBAL_PER_MINUTE` | 60 | 一个服务进程在一个滑动分钟内可接收的研究请求数，上限 6000。 |
| `ATLAS_RESEARCH_MAX_HISTORY` | 3000 | 一份研究数据库保留的运行总数，上限 100000。每次写入优先保留最新记录，每工作区最多 30 条。 |
| `ATLAS_RESEARCH_MAX_NOTES` | 5000 | 一份研究数据库可接收的研究笔记总数，上限 100000。每工作区最多 24 条，达到总量上限时拒绝新增，旧笔记仍可查看和删除。 |

配置须为 1 至对应上限内的整数，其余值回到默认值。运行触及频率限制时返回 HTTP 429 和 `Retry-After`。地址取自 ASGI 连接，由 Uvicorn 的受信代理设置决定是否转发真实客户端地址。应用本身不读取转发请求头。频率配额按服务进程计算，多进程或公开部署需在可信代理处设置共享配额和提供商预算。工作区凭证用于隔离匿名浏览器的笔记和历史。

前端以 JSON 布尔值明确选择记忆和图像传输。请求校验失败时，仅返回错误类别与位置范围，避免回显笔记或图像原文。
